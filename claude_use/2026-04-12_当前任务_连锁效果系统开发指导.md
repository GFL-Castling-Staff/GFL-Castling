# 2026-04-12｜当前任务｜连锁效果系统开发指导

本文档用于指导一个“可复用的连锁传导系统”设计与后续实现。该系统的定位不是单一技能，而是通用能力层，供主动技能、击杀追击、被动附伤和纯特效演出共用。

## 目标

第一版目标：

- 提供一个可复用的连锁传导逻辑模块
- 支持从触发点吸附首目标
- 支持多跳传导与每跳间隔
- 支持与独立特效模块联动
- 支持简单的目标过滤
- 支持目标死亡后不吞掉后续跳数
- 默认不判定 LOS，允许穿墙

暂不进入第一版的内容：

- 重复传导
- 剩余跳数灌注当前目标
- 按跳数衰减伤害
- 按目标数均摊伤害
- 倒地单位特殊交互
- 多条链之间的冲突抑制或合并

## 核心设计原则

不要把闪电链实现成“一个 projectile 自己完成全部跳跃”的黑盒。

建议拆成两层：

1. `ChainLightningLogic`
负责：
- 目标搜索
- 跳数推进
- 伤害模式计算
- 历史命中记录
- 下一跳决策

2. `ChainLightningVisual`
负责：
- A 到 B 的闪电弧特效
- 命中特效
- 音效
- 地面或角色附着效果

由逻辑层决定每一跳的起点和终点，再触发 visual 层播放表现。

## 建议模块拆分

建议按以下概念组织：

- `ChainEffectDefinition`
- `ChainExecutionContext`
- `ChainTargetFilter`
- `ChainDamageProfile`
- `ChainVisualProfile`

建议含义：

- `ChainEffectDefinition`：一条链的总配置入口
- `ChainExecutionContext`：一次实际触发时的运行态数据
- `ChainTargetFilter`：决定哪些目标合法
- `ChainDamageProfile`：决定每跳如何结算伤害
- `ChainVisualProfile`：决定每跳如何表现

## 第一版建议参数

建议一开始就把参数抽象出来，即使部分暂未实现：

- `first_target_acquire_radius`
- `jump_interval`
- `max_jumps`
- `jump_range`
- `max_total_chain_distance`
- `allow_repeat_target`
- `repeat_target_limit`
- `continue_when_target_invalid`
- `search_from_last_target_position`
- `damage_mode`
- `base_damage`
- `damage_falloff_per_jump`
- `split_damage_pool`
- `logic_key`
- `visual_key`

其中第一版实际启用的关键参数建议为：

- `first_target_acquire_radius = 5.0`
- `jump_interval = 0.12`
- `max_jumps = 5`
- `jump_range = 7.5`
- `max_total_chain_distance = 35.0`
- `allow_repeat_target = false`
- `continue_when_target_invalid = true`
- `search_from_last_target_position = true`
- `damage_mode = fixed`

## 第一版建议默认数值

用于性能与手感的保守起步值：

- 首目标吸附半径：`5.0`
- 每跳搜索半径：`7.5`
- 最大跳数：`5`
- 每跳间隔：`0.12s`
- 最大总传导距离：`35.0`
- 候选目标上限：`12`
- 单次链生命周期上限：`1.2s`
- 单目标命中上限：`1`

## 首目标规则

首目标不要求玩家精确点中敌人，而是以施法点或触发点为中心吸附范围内最近的合法目标。

推荐规则：

- 触发点为技能瞄准点、击杀点、命中点或其他外部事件点
- 在 `first_target_acquire_radius` 内搜索合法目标
- 取最近目标作为首目标
- 若无合法目标，则整条链直接结束

## 每跳流程

建议每条链维护独立上下文，至少包含：

- `source_id`
- `source_faction_id`
- `current_target_id`
- `current_search_origin`
- `jump_index`
- `remaining_jumps`
- `accumulated_distance`
- `hit_history`
- `per_target_hit_count`
- `damage_profile`
- `visual_profile`

每一跳流程建议为：

1. 若是首跳，则从触发点吸附首目标。
2. 校验当前目标是否仍可用于本跳结算。
3. 若目标有效，则执行本跳逻辑效果。
4. 记录本跳命中目标与位置。
5. 触发本跳 visual。
6. 等待 `jump_interval`。
7. 以当前命中位置为圆心搜索下一目标。
8. 若无目标或达到上限，则结束。

## 目标失效与死亡规则

第一版建议采用“不吞跳数”的保守规则。

具体规则：

- 本跳命中前若目标有效，则正常结算
- 下一跳搜索时，无论该目标是否死亡，都以“本跳记录的位置”作为下一跳搜索原点
- 若目标在本跳开始前已经失效，可跳过伤害结算，但仍允许从计划位置继续搜索

## 目标过滤

由于当前项目中载具/建筑与步兵逻辑差异很大，建议不要把类型判断写死在链模块内部，而是通过过滤器决定。

第一版建议预留三类过滤模式：

- `character_only`
- `vehicle_only`
- `all_hostile`

## LOS 与地形规则

由于当前引擎接口未暴露稳定的 LOS、穿墙、跨楼层判定能力，第一版建议明确采用：

- 不判 LOS
- 默认允许穿墙
- 默认允许跨楼层

## 伤害模式规划

建议枚举：

- `fixed`
- `falloff`
- `split_pool`

第一版只实现 `fixed`，但结构上不要写死成“固定伤害链”。

## 重复传导规划

第一版默认关闭重复传导：

- `allow_repeat_target = false`
- `repeat_target_limit = 1`

## 多条链并发规则

第一版推荐：

- 每次触发创建独立 `ChainExecutionContext`
- 各条链独立维护 `hit_history`
- 允许不同链命中同一目标
- 允许 visual 重叠

## 性能控制建议

第一版必须带上明确的保护措施：

- `max_jumps = 5`
- `jump_range = 7.5`
- `max_total_chain_distance = 35.0`
- `candidate_limit = 12`
- `chain_lifetime_limit = 1.2s`

## 与现有工程的结合建议

从当前工程结构看，推荐方向是：

- 技能入口由 `commandskill.as` 或其他触发器发起
- 链推进使用现有 `TaskSequencer` / 延时任务风格
- 每一跳由逻辑层创建两个实例：
  - 一个真实伤害或逻辑实例
  - 一个纯特效实例

不要把整个链行为塞进 projectile XML。

## 当前工程下的重要实现约束

如果从 `commandskill.as::handleChatEvent()` 直接进入连锁系统，并在同一调用链中执行 `getCharactersNearPosition()` 这类同步范围查询，当前工程环境下可能出现脚本死锁。

因此，当前实现应增加一条明确约束：

- 技能入口函数不要直接做连锁首目标范围搜索
- 技能入口只负责施法表现与参数打包
- 首目标搜索应优先改成异步 `make_query`
- 真正的 `ChainTask` 只在 `query_result` 返回并完成候选解析后创建

推荐最小分层：

1. `excuteXXXSkill()`
只做：
- 动画
- 音效
- 初始特效
- 构造 definition
- 投递 bootstrap task

2. `PendingChainQuery + handleQueryResultEvent`
只做：
- 发送首次范围查询
- 记录等待中的链请求
- 收到 `query_result` 后解析候选列表
- 创建 `ChainExecutionContext`
- 投递 `ChainTask`

3. `ChainTask`
只做：
- 按跳推进
- 纯内存选下一目标
- 伤害与视觉结算

对当前 OTS-14 而言，首目标查询应该从：

- `excuteOTS14Skill() -> triggerChainEffect()`

改成：

- `excuteOTS14Skill() -> make_query(characters) -> handleQueryResultEvent() -> startChainEffectFromCandidates()`

关键不是“把 query 挪到别的函数”，而是“把首次范围查询改成真正异步，再由回调续流程”。

## 第一版推荐范围

建议第一版只完成以下闭环：

- 通用连锁逻辑模块
- 首目标吸附
- 每跳间隔
- 固定伤害模式
- 默认不重复传导
- 当前目标死亡后继续传导
- 逻辑与特效分离
- 简单目标过滤

## 当前建议结论

当前最合适的实现方向不是“做一个闪电链技能”，而是“做一个可被多个技能和特效复用的连锁效果系统”。

但在当前工程下，要额外遵守一条实现前提：

- 任何首目标范围搜索都不要在技能入口同步调用链里完成
- 应优先通过异步 `query_result` 回调进入链初始化
