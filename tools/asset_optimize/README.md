# 资源优化工具（tools/asset_optimize）

RWR 是 32 位程序，整个游戏最多只能用 4 GB 地址空间。异向易位的资源很多，进图后离上限很近，
换几张图就可能出现 bad allocation 或卡在 80%。这套工具把三类已经实测有效的资源优化做成了
可以重复运行的脚本：**以后新增模型、音效、贴图，跑一下就行，不用记规则。**

## 最常用的两件事

**加了新资源之后**，在仓库根目录运行（或直接双击 `castling_assets.exe`，按菜单操作）：

```bat
python tools\asset_optimize\castling_assets.py all
```

它会依次处理模型、音效、贴图，最后自动复查一遍。

**提交或合并之前**，只做检查、不改任何文件：

```bat
python tools\asset_optimize\castling_assets.py check
```

全部通过时退出码是 0，有需要处理的问题时是 1，并且会逐条告诉你是哪个文件、什么问题、该运行哪个命令。

## 需要准备什么

**用 exe 的话什么都不用装。** 需要的外部程序已经放在 `bin/` 里了：

| 用途 | 用到的程序 | 说明 |
|---|---|---|
| 全部功能 | Python | exe 里已自带；直接运行 `.py` 的话需要 Python 3.8 及以上（只用标准库） |
| 音效 | SoX 14.4.2 | 已自带：`bin/sox/`（约 5 MB）。只处理音频，不需要 ffmpeg |
| 贴图 | texconv（微软 DirectXTex） | 已自带：`bin/texconv.exe`（约 1 MB） |
| 贴图、检查 | 原版游戏的 `media/packages/vanilla` 目录 | 你机器上装了游戏就有，常见 Steam 路径会自动找到；否则 `--vanilla <路径>` 或环境变量 `RWR_VANILLA` |

`bin/` 里的程序是第三方的，来源、版本和许可证见 [bin/README.md](bin/README.md)。
想用自己机器上的版本，可以用 `--sox` / `--texconv` 指定；音效也可以用 `--ffmpeg <路径>` 改用 ffmpeg。

## 各个命令

每个命令都可以单独运行，都支持 `--check`（只报告、不修改）和只处理指定文件。

| 命令 | 作用 | 例子 |
|---|---|---|
| `check` | 检查全部资源，只读 | `castling_assets.py check --only sounds` |
| `models` | 模型精简 | `castling_assets.py models gkd_ar_xxx.xml` |
| `sounds` | 音效规范化 | `castling_assets.py sounds new_shot.wav` |
| `textures` | 贴图压缩 | `castling_assets.py textures --explain foo.png` |
| `all` | 模型 → 音效 → 贴图 → 检查 | `castling_assets.py all` |

也可以直接运行对应的脚本：`optimize_models.py`、`optimize_sounds.py`、`optimize_textures.py`、`check_assets.py`。

每次运行的完整输出都会存到 `tools/asset_optimize/logs/`，文件名带时间。出问题时把对应的日志发出来即可。
`logs/` 不进 git。

## 规则，以及为什么

### 模型（`packages/GFL_Castling/models/*.xml`）

- **去掉标签之间的垃圾字符。** 旧工具会在每个 `>` 后面注入 1–2 个字符（如 `<model>GG`、`<voxel .../>C`）。
  它们没有意义，但游戏的 XML 解析器会为每一处都创建一个节点。
- **去掉内部体素。** 六个方向的邻居都存在、并且都绑定在同一根骨段上的体素，永远看不见，可以删。
  只在同一骨段内判断，是为了关节弯曲时不露洞。绑定序号会同步重排。
- 写入前每个文件都会自校验：骨架不变、每个体素恰好绑定一次、保留下来的体素颜色和骨段不变、
  被删掉的体素确实没有暴露面。任何一项不通过就保持原样。
- 有重复坐标、或同一个体素被绑到多根骨段的模型，只去垃圾字符、不删体素，并给出警告。
  这类文件请在建模工具里修好再导出。

**为什么**：游戏加载一个模型时会把整个 XML 解析成内存里的对象，文件越大瞬时占用越高。
铁血的 `sfd_boss_cerberus_gua.xml` 原来有 28 MiB、47 万个标签，加载时瞬间要约 237 MB，
之后约 200 MB 的地址一直被占着不还。内部体素还会常驻内存。

### 音效（`packages/GFL_Castling/sounds/*.wav`）

规范：**标准 WAV、PCM、16 位、单声道或立体声、采样率不超过 32000 Hz**，文件头必须是最简单的
44 字节布局（`fmt` 块 16 字节，后面紧跟 `data`）。

**为什么**：游戏读普通音效的方式很简单——固定读 44 字节文件头，把后面的数据原样交给声卡接口，
不做任何解码或转换，而且加载时就全部读进内存。所以：

- 采样率越高，占的内存越多。44100/48000 Hz 降到 32000 Hz，听感差别很小，内存少约四分之一到三分之一。
- 32 位浮点、24 位、带额外信息块的 WAV，在播放器里能正常播，但游戏会把它们当成 16 位数据误读，
  很可能是杂音。Ogg、MP3 不能用。
- 导出音效时请直接选“WAV，16 位 PCM，32000 Hz”。

需要保留更高采样率时可以用 `--rate 44100`，但请整个团队统一，不然检查会报错。

### 贴图

**只有同时满足下面全部条件的贴图才会被转成 DDS**（不透明的用 DXT1，带透明的用 DXT5）：

1. 所有引用都是这两种之一：`.particle` / `.material` 里的 `texture` 语句，
   或 `texture_filename="..."`（载具、武器、投射物的模型贴图）；
2. 长宽都是 2 的幂，最长边大于 128；
3. 不是灰度图，文件名不含 `normal` / `bump`；
4. 不在 `maps/`、`fonts/` 目录下；
5. 文件名在 mod 内唯一，不与原版贴图同名，也不被原版文件引用。

转换后脚本会把所有引用里的扩展名改成 `.dds`，并删除原图。

**不会转、也不应该手动转的：**

| 类别 | 原因 |
|---|---|
| 界面图标（`hud_icon` 等 `filename="..."` 引用） | DXT 是有损压缩，图标的细线和文字边缘会明显发糊 |
| `maps/` 下的图 | 地形高度图是数据，尺寸必须是 513×513；地形和效果混合图会被游戏逐像素读取 |
| `fonts/` 下的图 | 文字会糊 |
| 与原版同名的贴图 | mod 靠同名文件覆盖原版贴图，改了扩展名覆盖就失效 |
| 尺寸不是 2 的幂的 | 游戏读 DDS 时会把它放大到 2 的幂并重新压缩，画质和内存都吃亏 |

想知道某张图为什么没被转换：`castling_assets.py textures --explain 文件名.png`。

**为什么**：每张贴图除了显存里的一份，在游戏进程里还会多留一份副本。普通贴图每像素 4 字节，
DXT1/DXT5 每像素 0.5/1 字节。载具贴图是载具出现时才加载的，加载后一直占着，
所以一局里出现过的载具种类越多，内存涨得越多。

**新增载具或粒子贴图时**：照常放 PNG/JPG、引用里照常写原文件名，然后运行 `textures` 命令，
脚本会自己判断能不能转、并改好引用。想省这一步，也可以直接提供 DDS 并在引用里写 `.dds`。

## 实测效果

单机战役 map2_c、敌方铁血、同一个存档，游戏版本 1.98.1：

| 优化 | 效果 |
|---|---|
| 模型精简 | 进程地址占用少 310–345 MB；铁血模型加载造成的空置堆段 17 个 → 3 个 |
| 音效 32000 Hz | 音效占用约少 100 MB（降到 22050 Hz 能省 170–180 MB，但听感略闷） |
| 贴图压缩 | 场上有 9 种载具时约少 88 MB；载具越多省得越多 |
| 模型 + 音效 | 加载后 4 分钟：实际内存少 270 MB，地址占用少 454 MB |

没有覆盖到的：联机客户端、长局、多次换图；军方和帕拉蒂斯的模型没有逐个在游戏里看过。
加载时间不会因此变短。

## 排查

- **提示找不到 SoX / texconv**：确认 `tools/asset_optimize/bin/` 目录完整（exe 要和 `bin/` 放在同一个目录下）。
- **提示找不到 vanilla**：用 `--vanilla` 指定原版游戏的 `media/packages/vanilla` 目录。
- **某个文件显示“失败，未修改”**：脚本宁可不改也不会写坏文件。把 `logs/` 里对应的日志发出来。
- **想先看看会改什么**：任何命令加 `--check`。
- **改完想撤回**：这些都是普通的文件改动，用 git 还原即可。
- **用别的目录测试**：设置环境变量 `CASTLING_MOD` 指向另一份 `GFL_Castling` 目录。

## 文件说明

| 文件 | 说明 |
|---|---|
| `castling_assets.py` | 统一入口，带菜单；exe 就是用它打包的 |
| `optimize_models.py` | 模型精简 |
| `optimize_sounds.py` | 音效规范化 |
| `optimize_textures.py` | 贴图压缩 |
| `check_assets.py` | 检查（只读） |
| `common.py` | 公共部分：定位目录、查找外部工具、写日志 |
| `build_exe.bat` | 用 PyInstaller 把工具打包成单个 exe |
| `bin/` | 随工具附带的第三方程序：SoX、texconv |

仓库里现有的音效是用 ffmpeg 的 soxr 重采样器转的（当时的试听和实测用的就是那一批）；
工具现在改用 SoX，两者算法同源，转出来的时长和文件头相同，波形差别在听不出的量级。
